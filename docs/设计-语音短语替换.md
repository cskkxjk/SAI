# 语音短语替换（设计草案）

> 状态：测试中（分支 `feature/voice-phrase-replace`）。目标版本：v1.0.6+。

## 1. 目标

ASR 文字层的音素纠错只能处理「近音错字」，无法覆盖「识别出来就错、且读音差得远」的情况。
本功能在**音频层**做短语匹配：用户先录入一段语音并标注它应识别出的文字；正式听写时，
若录音中匹配到该短语，就用标注文字直接替换对应片段，不依赖 ASR 是否正确识别。

约束（已与需求方确认）：

- 短语数量 ≤ 50 条，单条时长 0.5–4s（更长的整句不推荐）。
- 只对麦克风听写生效；文件转录不启用。
- 优先级：**语音短语命中 > `hot.txt` 音素纠错 > `hot-rule.txt` 规则替换**。
- 命中时给出可见提示（方便调试）。

## 2. 现有链路（为什么这样做）

- 客户端采集原始 48k float32，发送前抽稀为 16k 单声道（`core/client/audio/recorder.py:148-150`）。
- 服务端按时间切片（15s/段、重叠 4s，无 VAD）整段离线识别；四个引擎均不支持流式
  （`core/server/engines/base.py:14`）。
- final 结果带 token 级全局时间戳（`core/protocol.py:88-91`），但听写路径客户端直接丢弃
  （`core/client/output/result_processor.py:199`）。
- 听写本身是「松手上屏」，所以匹配不需要实时：录音结束、final 结果到达后做一次即可。

结论：匹配放在**客户端**（能拿到整段录音缓冲、不引入服务端协议变更），
在 `ResultProcessor` 的 final 流程里、热词纠错之前执行替换。

## 3. 存储格式

`DATA_DIR/voice-phrases/`：

- `<id>.<n>.wav`：每条短语 1~3 份录音样本，16k 单声道 PCM16（原始语音，非特征）。
- `<id>.<n>.feat.npz`：MFCC 特征缓存（含 `version`），特征版本不匹配时自动重算。
- `voice-phrases.json`：索引 `{version, items: [{id, text, created_at, samples}]}`（原子替换写入，
  图形界面与客户端可能并发读写）。
- 同一文字的样本保存到同一个词条（`store.add` 默认 `merge=True`，上限 `MAX_SAMPLES=3`）；
  历史遗留的同文字多条词条在面板启动时由 `merge_duplicates()` 自动合并（不丢样本）。

选「原始语音 + 特征缓存」的原因：换特征/embedding 后端只需重算特征，不必重新录音，
天然支持后端插件化。空间开销极小：50 条 × 3s × 32KB/s ≈ 4.8MB。

**当前不用 ASR 模型做 embedding**：默认特征提取器是去掉 c0 的 12 维 MFCC，
逐句做 CMN（倒谱均值归一化，抵消麦克风/信道频谱偏移）+ 3 帧时间平滑（抑制帧级抖动），
匹配用子序列 DTW（起止自由），无额外模型、跨引擎一致；将来可以换成神经特征
（例如复用 ASR encoder 输出或专用声纹/KWS 模型），接口为 `features.py` 的 `mfcc()`
单一入口，wav 保留保证可迁移（特征版本号变化时缓存自动重算）。

## 4. 匹配流程（`core/client/voice_phrase/matcher.py`）

1. **候选区间**：匹配发生在 final 结果返回之前（录音一结束就做），拿不到 token 时间戳，
   因此用能量门限分窗（`segment_by_energy`，区间向两侧各放宽 0.3s，
   避免能量门限削掉起止低能量音节后模板比窗口还长）；`match()` 仍保留 `spans` 参数备用。
2. **粗筛**：对每个区间与模板，把特征按时间切成 4 段取均值，滑窗（步长 50ms）
   计算余弦相似度，取前 K（默认 5）个起点。开销 O(候选数 × 维度)，毫秒级。
3. **精筛**：对候选窗口做子序列 DTW（起止自由，numba 加速，缺失时退化为纯 Python）。
   距离按模板长度归一，这样窗口里的首尾杂音帧不会拖累整体分数；
   语音比样本说得快（窗口比模板短）时先把模板线性压缩到等长再比，慢则靠 DTW 拉伸对齐。
4. **判定**：距离 < `voice_phrase_threshold`（默认 8.0）才命中；同一**文字**的多份样本/多词条
   取最优（`_resolve` 按文字去重，同文字不互判歧义）；
   与次优模板差距不足 8% 时判为歧义丢弃，降低误报。
   距离量纲为逐帧平均欧氏距离（真实录音实测：同一句话不同次录音约 5~7.5，不同句子约 8.5+）。

命中结果：`PhraseMatch(phrase_id, text, start, end, score)`，`start/end` 为相对本次录音的秒数。

## 5. 替换与集成（已实现）

- `Recorder` 在语音短语开启时缓存整段 16k 音频（`_voice_cache`），松开录音键后
  先做匹配并 `ClientState.register_voice_matches(task_id)`，**再**发送 final——
  顺序反了会出现「服务端结果先回、匹配还没注册」导致替换丢失且结果残留。
- `ResultProcessor` final 分支：从终态消息（含错误/空白结果）统一 `pop_voice_matches`；
  用 `message.tokens/timestamps` 把命中区间映射到字符位置后替换为标注文字，再走既有的
  hot.txt / hot-rule 流程。token 由服务端对齐在 `text_accu` 上，客户端输出用的是 `text`：
  两者不一致时先在 `text_accu` 上定位 token，再用 difflib 把字符区间映射回 `text`
  （映射失败退回直接在 `text` 上定位），重复词场景不会错位。
- **繁体转换放在替换之后**：`tokens` 是简体，先转繁体会导致 token 在文中定位失败。
- 调试提示：命中后 Toast 显示「语音短语替换：<文字>（score）」（`voice_phrase_hint`）。

## 6. 分阶段

1. ✅ 特征/DTW/匹配核心 + 存储 + 单元测试（本分支第一版）。
2. ✅ 录音缓冲 + ResultProcessor 集成 + 配置项（开关/阈值/提示）：
   `core/client/voice_phrase/manager.py`（模板热重载 + match 入口）、
   `core/client/voice_phrase/replace.py`（音频区间→token→文本区间替换）、
   `Recorder` 缓存整段 16k 音频并在结束时匹配、`ClientState.voice_matches` 传递命中、
   ResultProcessor 在 hot.txt 之前替换并在命中时 Toast 提示；
   配置键 `voice_phrase` / `voice_phrase_threshold` / `voice_phrase_hint`（命中提示默认关闭，
   避免打扰上屏，调试时可开）。
3. ✅ 录入 UI（热词对话框新增「语音短语」页：录制、试听、标注、删除，最多 50 条）。
   录音不单独弹窗：页面上的「开始录制」是模式开关——按下后录音键改为录制短语，
   再点一次（取消录制）、离开本页或最小化到托盘即交还语音识别；模型未就绪时
   点「开始录制」会等待载入（客户端就绪后自动生效），未启动则提示先启动。
   模式生效后按住主录音键说话、松开即采集（0.5~4s，超时自动停止），
   音频留在页面内试听/保存/放弃；录制期间托盘图标与听写一样变红。
   面板与「语音测试」共用 `VoiceCapture`（`core/desktop_voice_phrases.py`）：
   pynput 监听录音键，事件经队列转投 Tk 主线程，Win32 用 `win32_event_filter`、
   macOS 用 `darwin_intercept` 屏蔽录音键避免触发系统行为（`ShortcutManager`
   的非 Windows 路径同样处理，macOS 需要辅助功能权限；注意 pynput 在 mac 上把
   CapsLock 报成一次切换事件，CapsLock 的“长按录音”语义在 mac 上受限）；
   录制期间写入 `DATA_DIR/logs/voice-capture.flag`（含启动器 PID 与 ts，原子替换写入，
   记录模式下每 30s 刷新 ts），客户端 `ShortcutManager` 在按键命中时直接查标记并暂停
   快捷键触发（且不阻塞按键，让启动器能收到），另有 0.5s 轮询兜底；启动器被强杀后按
   PID 判活清理残留，JSON 损坏或 ts 超过 120s 也按无效处理（避免一直占着麦克风）。
   标记生效时客户端还会**让出常开的麦克风**（`AudioStreamManager.suspend_for_capture`
   / `resume_after_capture`），避免蓝牙耳机这类“同一时刻只允许一条输入流”的设备
   互相抢麦导致采不到音频；GUI 采集按候选设备（所选→同名其它主机接口→默认）、
   采样率、延迟逐个回退，打开后确认能拿到数据再接受（“能打开但不出数据”的设备
   直接换下一个），设备只支持 48k 时自动重采样回 16k 模板。
   预热线程交付流时校验代际（`_open_generation`），disarm/重新 arm 后到达的旧流直接关闭，
   不会绑定到新一轮录制。
   页面上没有录音按钮：窗口保持可见且有焦点时按录音键即录制；离开本页、窗口最小化到托盘
   （`<Map>/<Unmap>`）或**应用失焦**（`<FocusOut>/<FocusIn>` + `focus_displayof`）都会
   立即交还录音键。macOS 上 CapsLock 无法按住说话（pynput 只报一次瞬时事件），
   `arm()` 会直接提示换键。
   客户端就绪/停止由启动器通知面板（`HotwordEditor.notify_client_ready/stopped`）。
   启动完成后窗口不再自动最小化到托盘（否则语音短语页无法接管录音键）。
4. ✅ 「测试替换」新增「语音测试」：按住录音键说短语，松开后直接匹配
   （`match_phrases`，阈值取 `voice_phrase_threshold`），命中则把标注文字填入
   「测试原文」并继续走 hot.txt / hot-rule.txt 流程；未命中时显示**最接近的短语、
   距离与阈值**（`best_candidates`）便于校准阈值。
   连续语音没有静音间隔时，`segment_by_energy` 会整段兜底切分，避免漏匹配。
