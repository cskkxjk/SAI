# 语音短语替换（设计草案）

> 状态：开发中（分支 `feature/voice-phrase-replace`）。目标版本：v1.0.6+。

## 1. 目标

ASR 文字层的音素纠错只能处理「近音错字」，无法覆盖「识别出来就错、且读音差得远」的情况。
本功能在**音频层**做短语匹配：用户先录入一段语音并标注它应识别出的文字；正式听写时，
若录音中匹配到该短语，就用标注文字直接替换对应片段，不依赖 ASR 是否正确识别。

约束（已与需求方确认）：

- 短语数量 ≤ 50 条，单条时长 0.5–4s（更长的整句不推荐）。
- 只对麦克风听写生效；文件转录不启用。
- 优先级：**语音短语命中 > `hot.txt` 音素纠错 > `hot-rule.txt` 规则替换**。
- 命中时给出可见提示（方便调试）。

## 2. 现有链路（为什么这样做）

- 客户端采集原始 48k float32，发送前抽稀为 16k 单声道（`core/client/audio/recorder.py:148-150`）。
- 服务端按时间切片（15s/段、重叠 4s，无 VAD）整段离线识别；四个引擎均不支持流式
  （`core/server/engines/base.py:14`）。
- final 结果带 token 级全局时间戳（`core/protocol.py:88-91`），但听写路径客户端直接丢弃
  （`core/client/output/result_processor.py:199`）。
- 听写本身是「松手上屏」，所以匹配不需要实时：录音结束、final 结果到达后做一次即可。

结论：匹配放在**客户端**（能拿到整段录音缓冲、不引入服务端协议变更），
在 `ResultProcessor` 的 final 流程里、热词纠错之前执行替换。

## 3. 存储格式

`DATA_DIR/voice-phrases/`：

- `<id>.<n>.wav`：每条短语 1~3 份录音样本，16k 单声道 PCM16（原始语音，非特征）。
- `<id>.<n>.feat.npz`：MFCC 特征缓存（含 `version`），特征版本不匹配时自动重算。
- `voice-phrases.json`：索引 `{version, items: [{id, text, created_at, samples, feature_version}]}`。

选「原始语音 + 特征缓存」的原因：换特征/embedding 后端只需重算特征，不必重新录音，
天然支持后端插件化。空间开销极小：50 条 × 3s × 32KB/s ≈ 4.8MB。

**当前不用 ASR 模型做 embedding**：默认特征提取器是去掉 c0 的 12 维 MFCC + 一阶差分
（共 24 维，对音量/增益不敏感、逐帧独立不受前后文影响），匹配用子序列 DTW（起止自由），
无额外模型、跨引擎一致；将来可以换成神经特征（例如复用 ASR encoder 输出或专用声纹/KWS
模型），接口为 `features.py` 的 `mfcc()` 单一入口，wav 保留保证可迁移。

## 4. 匹配流程（`core/client/voice_phrase/matcher.py`）

1. **候选区间**：优先用 final 结果的 token 时间戳构造语音区间（`spans`）；
   无时间戳时用能量门限分窗（`segment_by_energy`）。
2. **粗筛**：对每个区间与模板，把特征按时间切成 4 段取均值，滑窗（步长 50ms）
   计算余弦相似度，取前 K（默认 5）个起点。开销 O(候选数 × 维度)，毫秒级。
3. **精筛**：对候选窗口做子序列 DTW（起止自由，numba 加速，缺失时退化为纯 Python）。
   距离按模板长度归一，这样窗口里的首尾杂音帧不会拖累整体分数。
4. **判定**：距离 < `voice_phrase_threshold`（默认 0.45）才命中；同一短语多份样本取最优；
   与次优模板差距不足 8% 时判为歧义丢弃，降低误报。

命中结果：`PhraseMatch(phrase_id, text, start, end, score)`，`start/end` 为相对本次录音的秒数。

## 5. 替换与集成（待实现）

- `Recorder` 在存在语音短语时缓存整段 16k 音频（当前只缓存阈值前的 0.3s，
  `core/client/audio/recorder.py:55`）。
- `ResultProcessor` final 分支：用 `message.tokens/timestamps` 把命中区间映射到字符位置，
  替换为标注文字（token→字符位置用累计长度 + difflib 对齐 `text` 与 `text_accu`），
  然后再走既有的 hot.txt / hot-rule 流程。
- 调试提示：命中后 Toast 显示「语音短语替换：<文字>（score）」。

## 6. 分阶段

1. ✅ 特征/DTW/匹配核心 + 存储 + 单元测试（本分支第一版）。
2. ✅ 录音缓冲 + ResultProcessor 集成 + 配置项（开关/阈值/提示）：
   `core/client/voice_phrase/manager.py`（模板热重载 + match 入口）、
   `core/client/voice_phrase/replace.py`（音频区间→token→文本区间替换）、
   `Recorder` 缓存整段 16k 音频并在结束时匹配、`ClientState.voice_matches` 传递命中、
   ResultProcessor 在 hot.txt 之前替换并在命中时 Toast 提示；
   配置键 `voice_phrase` / `voice_phrase_threshold` / `voice_phrase_hint`。
3. 录入 UI（热词对话框新增「语音短语」区：录制、试听、标注、删除、阈值测试）。
4. 端到端验证（Windows 实机 + mac 冒烟）、CHANGELOG/readme、可选的默认阈值校准。
